# Domain-Driven Design

Use DDD in proportion to the business behavior being changed.

- Name concepts in Vocora domain language.
- Keep each invariant and state transition under one authoritative owner.
- Keep provider SDK, persistence, framework, and process details outside domain
  decisions.
- Use explicit ports at genuine external boundaries.
- Keep vocabulary, learning-path, listening, exercise, and learner-progress
  rules out of presentation and infrastructure code.

Do not create aggregates, entities, value objects, repositories, or domain
events for ceremony.
